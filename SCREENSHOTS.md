# Screenshot analyzer: implementation and operator guide

## Member workflow
Upload one PNG, JPEG or WebP under 8 MB in general-chat, a sport bet-discussion room, or a private league discussion/picks/upload room. Automatic detection ignores winning-tickets and news feeds. The bot reads the image and replies with **Review my slip**; only the uploader can open the private review.

Alternatively run `/analyze-image image:<attachment>` in a discussion channel. Optional sport, book and from options set the sport, sportsbook and actual starting game date (YYYY-MM-DD UTC). Image labels such as "Today" never establish a calendar date. When sport, bookmaker branding or date is missing, verify them in the private form. The selected default book is Hard Rock Bet Florida and is labeled separately from image branding.

1. Review names, markets, direction, thresholds, games and visible wager metadata.
2. **Edit Legs** corrects sport, sportsbook, actual date, selections and visible odds/amounts. Each leg uses `name | market | direction | line | game`; blank fields mean unknown. For example: `Jaxon Smith-Njigba | receiving_yards | at_least | 70 | NE vs SEA`. Use a full game name or an exact event ID if a matchup is ambiguous. Directions are over, under, at_least, yes or no. Moneyline uses team name with market moneyline; spread uses team name and signed line. Do not change an existing wager just to force a current match.
3. **Re-Read Image** retries recognition; a clearer new image can be submitted with the command. **Cancel** stops the workflow. Screens expire after 30 minutes or bot restart is not required (state is in SQLite).
4. **Analyze** first validates the confirmed selections against current odds. Missing/expired/ambiguous selections stop the flow with a correction message. No odds are invented. A 70+ integer threshold is matched only to equivalent Over 69.5, not Over 70; alternate-market coverage is required.
5. Review the exact current quotes and displayed destination. **Analyze and post to sport chat** runs the existing cited research analyzer and publishes the report to the matching NFL/NBA/MLB/NHL/college discussion room. You and the bot must have destination access. Private-source uploads are never moved automatically without this explicit confirmation. Neither the original image nor wager amounts are reposted.

## What is delivered
Screenshot extraction and editing; preserved raw reads and separate confirmed tickets; current sportsbook resolution; cited per-leg/whole-ticket research through existing providers.analyze; professional Discord embeds; explicit confirmation before publication; channel routing based on the confirmed sport. No wagering/payment functionality.

Phase 3/4 statistical models are NOT implemented. Independent hit probabilities, correlation-adjusted parlay probability, fair odds, EV, calibrated ratings and mathematically safer alternatives remain unavailable/null. Qualitative correlation discussion comes from the existing research engine. Statistics/injury freshness is reported when found in cited sources; missing structured inputs are not filled from memory.

Initial adapter uses common Hard Rock labels and supports single/multiple games and alternate integer thresholds. It maps receiving/rushing/passing yards, receptions, passing TDs, ATTD, first TD, total TDs, moneyline/spread/game totals, basketball points/assists/rebounds, baseball hits/home runs/strikeouts and hockey shots. Recognition can preserve unsupported wording, but unsupported markets cannot proceed to analysis. DraftKings/FanDuel can be selected for matching; their screenshot layouts have not been acceptance-tested. One image and one sport per slip, maximum 12 legs. No historical or in-play analysis.

## Configuration and deployment
Existing variables reused: DISCORD_BOT_TOKEN, DISCORD_GUILD_ID, OPENAI_API_KEY, ODDS_API_KEY, DATABASE_PATH. Added: VISION_MODEL (default gpt-4.1), VISION_DAILY_LIMIT (30), SCREENSHOT_AUTO_DETECT (false unless enabled). Daily vision quota is additional to research/odds quotas; re-reads consume it. Secrets remain in local env files excluded from packages.
Enable the application's Message Content Intent and existing Server Members Intent. Automatic detection adds GuildMessages and MessageContent gateway intents. Bot channel permissions: View Channel, Send Messages, Read Message History, Embed Links. Members need Attach Files for uploads, Use Application Commands for commands, and access to the destination.
Run npm test, npm run register and restart npm start. Registration replaces this dedicated application's guild commands. The news bot does not need new privileges. NBA/NHL discussion destinations were added without resetting existing permissions.

## Database and files
New migration: migrations/002-screenshots.sql. screenshot_slips stores owner/message/channel, source attachment URL, immutable initial raw JSON, editable draft, confirmed JSON, current matched quotes, result JSON, status/revision, creation/update/expiry. screenshot_reads stores each recognition attempt separately. Probability/fair-odds/EV fields are null in the result. Source images remain Discord attachments; no local image copy is retained by the bot. Discord attachment URLs can expire; re-upload if re-read fails. Local database contains slip data; restrict operator access. Records are retained for debugging; cancellation stops work but does not delete records.

Created: src/screenshots/{vision,normalize,store,discord}.js; migrations/002-screenshots.sql; test/screenshots.test.js; SCREENSHOTS.md. Modified: src/providers.js (reuse safe request wrapper), src/bot.js (handler/intents), src/commands.js (command registration), .env.example. Local .env enables automatic detection. No new npm dependencies. API: OpenAI Responses image input with strict JSON schema and store:false; The Odds API via existing authenticated client; Discord via existing discord.js client.

## Verification and limits
Live OpenAI test on the embedded supplied screenshot recognized all six original names, thresholds 70/15/25/26/25/64, at_least direction, shared NE vs SEA game, +4500 odds, $5 wager and $230 payout. It appropriately left missing branding and ambiguous sport/date for user confirmation. Recognition is fallible: early test reads misread odds or invented a matchup; the extraction instructions/model were corrected and the final sample verified. Always inspect the private review.
Automated tests cover file safety/size, owner and revision isolation, raw-versus-edited storage, alternate thresholds, duplicate/expired/unmatched odds, confirmation-before-analysis, destination access and explicit publication. Discord/OpenAI recognition and command registration are live checks; posting flow is tested with simulated Discord interactions and odds to avoid publishing test reports into member channels. The sample has no verifiable calendar date, so its current sportsbook eligibility cannot be asserted. It was not assigned invented probabilities or treated as a live ticket.
